# 实现计划 v1

## 执行原则

- 本文是实施基线；任务定义在批准/执行后冻结，checkbox 与证据字段可更新。
- 默认一次只执行一个任务。每个任务开始前复核依赖、工作树和批准状态。
- Coder 不自行扩大范围；发现需求冲突时停止并触发 revision workflow。
- 每完成一个任务，运行该任务验证并记录证据；阶段结束运行仓库级 `npm run check`。

## 阶段 0 — 决策与契约

- [ ] **PE-001：记录架构与数据安全决策**
  - **依赖：** 无
  - **影响路径：** `docs/adr/`, `docs/security/`
  - **工作：** 编写 ADR，确认 SDK 子会话优先、双包边界、Markdown source of truth、版本冻结/迁移规则；记录模型输入、计划文件和源码探索的数据流及威胁。
  - **完成标准：** ADR 包含替代方案和后果；安全文档覆盖项目配置信任、路径逃逸、prompt injection、敏感信息、审批及取消。
  - **验证：** 文档链接有效；与 `AGENTS.md`、Pi 公共 SDK/extension API 无冲突。

- [ ] **PE-002：定义命令、配置和计划文件 contract**
  - **依赖：** PE-001
  - **影响路径：** `docs/plugin-contracts/plan-execute.md`
  - **工作：** 固化命令参数、非交互确认方式、配置 precedence、PlanBundle/ExecutionReport、目录结构、状态机、错误码和 migration preview。
  - **完成标准：** 每个命令都有输入、输出、审批点、取消和恢复语义；明确 v1 不自动 Git 写操作。
  - **验证：** contract 覆盖需求 R1–R8，并列出后续兼容策略。

## 阶段 1 — 领域包与持久化

- [ ] **PE-101：建立 `@mgood-pi/plan-execute` workspace**
  - **依赖：** PE-002
  - **影响路径：** `packages/plan-execute/`, root workspace config
  - **工作：** 创建 ESM strict TypeScript 包；定义配置、PlanBundle、任务、版本事件和 ExecutionReport 的公开类型及 TypeBox schemas。
  - **完成标准：** 无 Pi 注册副作用；所有外部输入通过 schema；runtime 依赖声明正确。
  - **验证：** schema 正反例单测、typecheck、build、pack validation。

- [ ] **PE-102：实现安全的计划路径与存储策略**
  - **依赖：** PE-101
  - **影响路径：** `packages/plan-execute/src/config*`, `src/paths*`, tests
  - **工作：** 实现 collaborative/personal/custom 解析、slug、仓库根检测、Git ignore 状态查询接口、路径规范化和符号链接/越界防护。
  - **完成标准：** 不修改 Git；返回可展示的 tracked/ignored/untracked 状态；拒绝非法根目录和冲突 slug。
  - **验证：** 临时仓库测试正常路径、`..`、绝对路径、symlink、空配置和自定义目录。

- [ ] **PE-103：实现确定性 Markdown renderer/parser**
  - **依赖：** PE-101
  - **影响路径：** `packages/plan-execute/src/markdown*`, fixtures, tests
  - **工作：** 从 PlanBundle 生成 README、CONTEXT、requirements、implementation、HISTORY；解析受支持 schemaVersion，保留稳定任务 ID 和规范化格式。
  - **完成标准：** 同一输入字节级稳定；未知 schema 失败并给出迁移提示；正文不能控制输出路径。
  - **验证：** golden tests、round-trip tests、恶意标题/frontmatter fixture。

- [ ] **PE-104：实现原子 PlanRepository 和版本策略**
  - **依赖：** PE-102, PE-103
  - **影响路径：** `packages/plan-execute/src/repository*`, `src/revision*`, tests
  - **工作：** 实现草稿创建、预览、发布、current pointer、revision/hash 并发门、状态/证据更新、HISTORY 追加及 supersede transaction。
  - **完成标准：** 崩溃不会暴露半个计划包；并发写返回冲突；已冻结语义字段不能原地改变。
  - **验证：** 故障注入、并发、取消、重复调用幂等和版本迁移 contract tests。

## 阶段 2 — Planner 编排

- [ ] **PE-201：抽象 Planner/Coder 会话端口和模型解析**
  - **依赖：** PE-101
  - **影响路径：** `packages/plan-execute/src/orchestration*`, tests
  - **工作：** 定义可注入的 AgentRunner、ModelResolver、ApprovalGate、RepositoryInspector；传递 AbortSignal 和结构化诊断。
  - **完成标准：** 领域测试无需真实 Pi/TUI/模型；不存在模型时不会隐式回退。
  - **验证：** fake adapter 测试成功、模型缺失、超时、中止和 malformed output。

- [ ] **PE-202：实现 Planner workflow**
  - **依赖：** PE-104, PE-201
  - **影响路径：** `packages/plan-execute/src/planner*`, bundled role prompt, tests
  - **工作：** 组织简短请求、只读仓库上下文和内置角色；限制澄清轮次；校验 PlanBundle；产生路径/Git/模型/文件 diff 预览后才发布。
  - **完成标准：** 用户无需提供模板；Planner 无文件写工具；取消/拒绝不发布；模型输出无法指定任意路径。
  - **验证：** fixture workflows 覆盖直接规划、需澄清、拒绝保存、注入文本和无效 JSON。

- [ ] **PE-203：实现 revision impact analyzer**
  - **依赖：** PE-104, PE-202
  - **影响路径：** `packages/plan-execute/src/revision*`, tests
  - **工作：** 将变化分类为 draft amendment 或 new version，生成 old-to-new task disposition 和 migration preview。
  - **完成标准：** active 版本语义变化必建新版本；carry-forward 带证据；发布前需要批准。
  - **验证：** 未执行小修、部分执行范围变化、架构变化、放弃、并发 revision 测试。

## 阶段 3 — Coder 执行引擎

- [ ] **PE-301：实现任务选择和执行状态机**
  - **依赖：** PE-104, PE-201
  - **影响路径：** `packages/plan-execute/src/execution*`, tests
  - **工作：** 选择下一个依赖满足的任务，建立执行 lease，记录起始 HEAD/dirty 摘要，处理 pending/in-progress/completed/failed/blocked/cancelled。
  - **完成标准：** 同一任务不会被两个会话同时执行；默认单任务；恢复不依赖聊天记录。
  - **验证：** dependency、lease、重复执行、中止和 stale in-progress 恢复测试。

- [ ] **PE-302：实现 scoped Coder workflow 与验证门**
  - **依赖：** PE-301
  - **影响路径：** `packages/plan-execute/src/coder*`, bundled role prompt, tests
  - **工作：** 只发送单任务上下文，解析 ExecutionReport，执行/采集允许的验证命令，区分模型声明与宿主证据。
  - **完成标准：** 无执行批准不调用 Coder；验证失败不勾选；越界请求停止并报告 revision 建议。
  - **验证：** fake coder 覆盖成功、部分修改、验证失败、模型谎报成功、取消和范围冲突。

## 阶段 4 — Pi 插件适配

- [ ] **PE-401：建立 `@mgood-pi/plugin-plan-execute`**
  - **依赖：** PE-202, PE-203, PE-302
  - **影响路径：** `plugins/plan-execute/`
  - **工作：** 声明 Pi manifest，注册 `/mgood:plan`、`/mgood:plan-status`、`/mgood:execute`、`/mgood:revise`、`/mgood:plan-history`；接入 model registry 和 SDK AgentSession。
  - **完成标准：** 工厂无后台副作用；资源懒加载并 shutdown 幂等；命令不遮蔽 built-in。
  - **验证：** 注册/lifecycle integration tests，SDK adapters 使用 fake sessions 测试。

- [ ] **PE-402：实现交互审批和非交互退化**
  - **依赖：** PE-401
  - **影响路径：** `plugins/plan-execute/src/ui*`, command tests
  - **工作：** TUI 展示模型、路径、Git 状态、任务和 diff 摘要；处理取消。print/json/rpc 下输出结构化预览并要求显式确认参数。
  - **完成标准：** `ctx.hasUI`/mode 守卫完整；任何写执行都有可测试审批门；错误包含安全修复方式。
  - **验证：** TUI fake、print/json/rpc command contract tests。

- [ ] **PE-403：加入状态可发现性**
  - **依赖：** PE-401
  - **影响路径：** `plugins/plan-execute/src/status*`
  - **工作：** 提供轻量状态/进度显示，包含当前 plan/version/task/model；无 UI 时不注册交互组件。
  - **完成标准：** 状态不泄露计划正文/凭据，不启动常驻 watcher/timer。
  - **验证：** session 切换、reload、shutdown 和无 UI 测试。

## 建议交付切片

1. **Milestone A — Plan only：** PE-001 至 PE-202。能从简短请求安全生成、预览和保存计划包。
2. **Milestone B — Revise：** PE-203。能在未执行和部分执行场景正确版本化。
3. **Milestone C — Execute one：** PE-301 至 PE-402。能经审批让低成本 Coder 执行单任务并验证/恢复。
4. **Milestone D — Productize：** PE-403 至 PE-502。完善状态、文档和发布质量。

每个 milestone 均应独立可演示；不要在 Milestone A 就引入自动连续执行或 Git 写操作。
